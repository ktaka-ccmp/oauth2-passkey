## Description

Add browser-level end-to-end tests that exercise the full authentication flow including JavaScript execution, DOM interaction, and real browser behavior.

### Current Test Coverage

- **Unit tests**: Comprehensive coverage of individual modules
- **Integration tests**: 40 HTTP-level tests using mock OIDC provider and direct API calls (`oauth2_passkey_axum/tests/integration/`)
- **Security tests**: 43 consolidated security scenario tests (`oauth2_passkey_axum/tests-security/`)
- **E2E tests** (Phase 1): 4 Playwright tests covering passkey register/login and OAuth2 popup login (`tests-e2e/`)

### Gap (areas E2E exercises that HTTP tests cannot)

- WebAuthn JS APIs: `navigator.credentials.create/get`
- Signal APIs: `signalAllAcceptedCredentials`, `signalUnknownCredential`
- FedCM: `navigator.credentials.get({ identity: ... })`
- Popup window + `postMessage` flow used by the OAuth2 popup
- Conditional UI / autofill on the login page

### Considerations

- WebAuthn/Passkey requires browser-level testing (virtual authenticator)
- Chrome DevTools Protocol supports virtual authenticator for testing
- Playwright + Chrome's CDP virtual authenticator works (proven in Phase 1)
- WebAuthn rejects IP-literal origins → must use `localhost`, not `127.0.0.1`
- CI integration requires headless browser support
- Test infrastructure adds TS/Node to a Rust workspace

## Approach

Playwright + TypeScript with Chromium's CDP virtual authenticator
(`WebAuthn.addVirtualAuthenticator`). A standalone `mock-oidc` workspace
member serves as the OIDC IdP so flows can run without external Google
endpoints. Tests target `demo-both` running on `localhost`.

Phase 1 (committed): foundation + smoke + passkey + OAuth2 tests.
Phase 2 (pending): expanded coverage, CI integration, brittleness
mitigations.

## Decision Log

### 2026-02-26: Migrated from ToDo.md

- Context: Migrating incomplete tasks from ToDo.md to issue tracking system
- Decision: Create as low-priority, large-difficulty issue
- Reason: Significant infrastructure investment; current integration tests provide good coverage. Worth doing eventually but not urgent

### 2026-05-12: Phase 1 completed

- Context: Manual regression testing on `demo-live` after each change had become a bottleneck; only happy-path flows were verified.
- Decision: Adopt Playwright TS + Chrome CDP virtual authenticator. Build a standalone `mock-oidc` binary for deterministic OIDC. Use `demo-both` as the system under test.
- Reason: Playwright Rust bindings are immature; TS is the de-facto path. CDP virtual authenticator handles passkey flows without real hardware. Standalone mock keeps E2E offline-deterministic.
- Outcome: 4 tests pass in ~6s (smoke ×2, passkey register-then-login, OAuth2 popup login). `mock-oidc` mirrors `axum_mock_server.rs`; consolidation deferred to Phase 2.
- Surprises: WebAuthn rejects IP-literal origins (must use `localhost`); `/o2p/user/logout` only redirects when `?redirect=` is supplied; new-user OAuth2 triggers passkey promotion popup (disabled for now via `O2P_PASSKEY_PROMOTION=disabled`).
